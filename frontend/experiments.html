CO1: End-to-End Machine Learning Lifecycle

Data ingestion, feature engineering, regularized modeling, FastAPI serving, and user interaction

Complete Request Flow Architecture

A prediction request travels through 6 distinct stages from frontend user action to rendered ETA:

  1. User Input: Origin location, destination location, departure date & time, and optional traffic override submitted via HTML form.
  2. Geocoding & Routing: FastAPI queries OpenStreetMap Nominatim for coordinates and OSRM API for road geometry, distance (km), and turn steps.
  3. Real-time Context: Open-Meteo API retrieves ambient temperature (°C) and precipitation (mm). Departure hour and day of week are extracted.
  4. Feature Preprocessing: Inputs are transformed via Scikit-Learn ColumnTransformer (StandardScaler for continuous variables, OneHotEncoder for categoricals). Fitted strictly on training split to prevent leakage.
  5. Inference Execution: Preprocessed vector (17 dimensions) is evaluated through Ridge and Lasso regression models in memory. Sanity checks enforce positive finite outputs.
  6. ETA Calculation & Delivery: Predicted minutes are added to departure datetime to compute arrival ETA, rendered into Leaflet interactive map and condition cards.

Objective Architectural Trade-Off Analysis

Neither paradigm is unconditionally superior across all real-world deployment criteria:

Linear Regularized (Ridge & Lasso)

Pros: Smooth monotonic extrapolation; zero step discontinuities; $O(1)$ fast dot-product inference; immune to local leaf overpartitioning.
Cons: Cannot naturally model non-linear rest-stop thresholds (e.g. journeys > 300km) without manual interaction features.

Decision Tree Regressor

Pros: Captures piecewise non-linearities and threshold speed tiers; achieves lower test MAE (37.9 mins) and RMSE (66.9 mins).
Cons: Output is piecewise-constant; cannot extrapolate beyond the bounding box of feature training data; higher variance than regularized linear regressions.
